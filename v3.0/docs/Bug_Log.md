# Atlas 3.0 Bug Log

## 使用规则

本文件只记录能从 `project_log.txt`、保留源码或明确归档检查中确认的问题。`已解决` 表示原日志有后续验证；`部分解决` 表示只通过部分输入；`文档性缺口` 不等同于程序故障。

## A3-B01

- 日期/阶段：初始化阶段
- 现象：1.0、2.0 与 3.0 数据分散在多份 JSON。
- 原因分析：每个阶段独立开发并使用不同文件名。
- 解决方法：创建 atlas_full_data.json/atlas3_data.json，并在主程序中迁移旧数据。
- 验证依据：主程序能显示 Profile、Skills、History、Plan、Emotion 和 Recommendation。
- 当前状态：**已解决**
- 防止复发：保留原始错误文本；一次只改一个变量；修复后重新执行最小测试并写入日志。

## A3-B02

- 日期/阶段：整合阶段
- 现象：六个阶段分别可运行，但不利于最终演示与长期维护。
- 原因分析：缺少统一菜单和统一数据结构。
- 解决方法：建立 atlas3_main.py 并合并六阶段。
- 验证依据：日志记录 Atlas 3.0 主程序启动和各模块调用。
- 当前状态：**已解决**
- 防止复发：保留原始错误文本；一次只改一个变量；修复后重新执行最小测试并写入日志。

## A3-B03

- 日期/阶段：数据质量
- 现象：早期输入可能含重复前缀或口语化字段。
- 原因分析：直接保存终端输入，没有统一清洗规则。
- 解决方法：后续版本保留原始记录，同时在新代码中使用固定字段。
- 验证依据：原始日志仍保留，未被覆盖。
- 当前状态：**部分改善**
- 防止复发：保留原始错误文本；一次只改一个变量；修复后重新执行最小测试并写入日志。
